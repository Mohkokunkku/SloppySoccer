# Argentina adult model auditions

## Scope and acceptance
Create a separate feature branch and a real, production-built 3D audition gallery with 12 original adult Argentina candidates: P01–P10 outfield and K01–K02 keepers. User picks four outfield and one keeper before any game replacement. Match physics, roles, existing Spain/Argentina dispatch, audio, labels, result storage and disabled deployment automation stay unchanged. Branch starts from the latest tested work; no merge/push/deploy without a new request.

## Direction contract
THESIS: A football-toy casting shelf, led by actual articulated characters rather than illustrated placeholders. Adult here means smaller relative heads, longer legs, tapered torsos, defined jaw/chin/brow and confident neutral expressions—not merely darker skins, beards or angry faces.
OWN-WORLD: Inherit the established satin-plastic/oak world and local Arial Black/Trebuchet stacks. Argentina sky blue #75B7DA, white #F7F8F4, navy #172C3B, warm oak #C89F70, soft cool ground #EDF2F3. No licensed marks or real-player likenesses.
STORY: Inspect all numbered candidates, rotate/pose one at full scale, compare against unchanged Spain/current Argentina, then shortlist exactly four plus a keeper. Audition does not apply the lineup.
FIRST VIEWPORT: A large full-body 3D inspector with model identity and comparison controls beside it; below, a 4-column casting shelf of all 12 rendered models. Portrait thumbnails come from the same real geometry. Phone: full-body inspector then two-column shelf, no horizontal overflow.
FORM: Code-led local extension inside the incumbent game identity; user explicitly requested at least 10 alternatives. Impeccable context engine was unavailable; no generated-image or concept-seed claim. Existing DESIGN.md remains historical authority where current code has not superseded it (roster/country facts come from runtime).
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance. For this extension, preserve existing DESIGN.md, document differences here, and identify screenshots as captures of procedural Three.js models.

## Shared modeling contract
Factory file `src/argentina-candidate-models.ts`, exclusively owned by modeling worker. Export:
- `export type ArgentinaCandidateId = 'P01' | ... | 'P10' | 'K01' | 'K02'`.
- `export interface ArgentinaCandidate { id: ArgentinaCandidateId; name: string; role: 'outfield' | 'keeper'; build: string; hair: string; face: string; description: string }`.
- `export const ARGENTINA_CANDIDATES: readonly ArgentinaCandidate[]` in P01–P10,K01,K02 order.
- `export function createArgentinaCandidate(id: ArgentinaCandidateId): FigureRig` (type-only import from `./scene`). Each call returns independently disposable geometry/materials. root.userData.candidateId set. Invalid runtime ID throws a clear Error, never silently substitutes.
- `export function disposeArgentinaCandidate(rig: FigureRig): void` deduplicates disposal per object inside rig, does not dispose another instance's resources.
Y up, face +Z, feet near Y=0; height ~3.1–3.5, head <=0.18 total height, shoulder width ~0.9–1.35. Real raised facial features, flatter eye shapes, firm jaw/chin, neck and athletic calf/thigh anatomy. Legs/arms arrays length2 with proper hip/shoulder pivots; optional actual knee/elbow hierarchy is welcome. No floating hair/gloves/beard, pinched necks or printed celebrity faces.
Distinct silhouettes/build/face/hair across all12, not recolors. Suggested spectrum: broad clean-cropped anchor, slim side-part playmaker, tall cropped striker, compact shaven veteran, lean curly winger, medium swept-back engine, heavy buzz-cut enforcer, lean tied-back technician, wavy-haired sweeper, angular fringe poacher; tall charcoal/sky keeper and broader dark-green/sky keeper. Diverse skin/hair features without assigning ethnicity/personality stereotypes. Satin plastic, navy shorts, Argentina vertical sky/white stripes; keeper gloves/cuffs and long sleeve variant. No runtime scene.ts/character-id.ts changes.
